# rom_data/settings: pricing, audits, adjustments, service menus

This folder covers Transformers Pro v1.80 (`tf_180`, Stern SAM). It is regenerated by
`TF_ROM=/path/tf_180.bin python3 rom/tools/settings_extract.py`, which also writes the MPF package files
`rom/mpf_package/service_menu.json`, `service_menu.md` and `config/settings.yaml`. The script reads the ROM through
`rom/tools/rom.py`, the decompile `rom/code/tf_decompiled.c` and the emulator logs in `emu/`.

The emulator harness is `rom/tools/settings_emu.cpp` (libpinmame with the ARM hook; port of Tron's harness).
`settings_extract.py --scripts` writes the scripts `emu/t1.txt` .. `emu/t6.txt`. Run each one with a fresh NVRAM
(the harness makes and removes a temp vpm folder): `PINMAME_NOJIT=1 settings_emu emu/tN.txt tN.log`.
The logs here have the per-second `audit_add` lines for counters 59-64 removed, and t6 has its `adj_get` lines
folded into `emu/t6_adj_get_counts.txt`. `t1` also writes `ram_usa.bin` (RAM 0x30000-0x40000) into the working
directory; it is not kept here because it holds a copy of ROM tables.

Every row has a `tag`, which gives the strongest evidence for that row:
- `observed`: seen in the emulator. The matching log is in `emu/`.
- `code`: read from tables or disassembly.
- `inferred`: reasoning only.

All addresses are hex. 0x04xxxxxx are ROM tables, 0x30000-0x34057 is the RAM copy of the ROM made at reset
(the same bytes as the file; checked against the RAM dump), 0x0210xxxx/0x0211xxxx is NVRAM.

## Files
### pricing.json / pricing.csv
- `credit_system`: the struct at 0x040ce04c, identical in layout and values to Tron's:
  - state at NVRAM 0x2111008 = {s32 pos, u8 credits, ~checksum8}
  - pricing pointer table at RAM 0x32324 (index = adj 28 value; 68 = CUSTOM record at NVRAM 0x2110808)
  - custom coin door at 0x2110824, custom ladder at 0x211089c
  - slot counters 2-6 (list 0x040ce016)
  - adjustments 28 (pricing), 62 (coin delay), 34 (free play) and 33 (credit limit)
  - meter 1, units counter 7, credits counter 1, lockout output 5
- `algorithm`: pseudo-code of coin task 0x3f00 (created by 0x4164), credits_add 0x3d40, display 0x44a4 and the
  fraction function 0x41f8, with addresses.
- `presets[]` (pricing.csv has one row per preset): same columns as Tron. Names are the record's msg (0x2b2+i).
  TF has four presets more than Tron (NORWAY 5-8 at 38-41), so every preset index from 38 on is shifted by 4:
  USA 10 is 66 (Tron 62), CUSTOM is 68 (Tron 64).
  - `coin_door`: a table of 12-byte entries {u32 unit value in 1/100 currency, u8 units per slot[5]}; `unit_index` selects one.
  - `slotN_units`: units per coin on slot N. Slot 1 = LEFT (PinMAME key 3), 2 = CENTER (key 4), 3 = RIGHT (key 5),
    4 = FOURTH (key 6), 5 = FIFTH (observed for keys 3-6 in emu/t2.log).
  - `ladder`: credits awarded at each unit position; the position wraps at `ladder_len`.
  - `service_summary`: the text the ROM's own summary function 0x9ff8 (via 0xa438(buf, record, font 0, width 128, mode -1))
    produced, observed for all 68 presets in emu/t3.log.
  - `factory_default_for`: countries whose factory default selects the preset (U.S.A. uses the table default 66).
- `verification_log`: emulator lines from emu/t2.log:
  - USA 10: 3 quarters (key 3) = 1 credit; $1 (key 4, 4 units) then shows "CREDITS 2 1/2"; a quarter on key 5 gives credit 3
    and one on key 6 shows "CREDITS 3 1/3".
  - GERMANY 2 (24): 1 EUR (key 4, 10 units) = +2 credits, 2 EUR (key 5) = +5, 50 cent (key 3) = +1.
  - EURO 3 (13): 50 cent = 1 credit, 1 EUR = 3.
  - FREE PLAY display, CREDIT LIMIT 4 (a fourth dollar adds no credit; TOTAL PAID CREDITS still counts the ladder value)
    and COIN INPUT DELAY OFF (61: coin counted 0.05 s after the switch instead of 0.49 s).
  - FREE GAME LIMIT: with adj 25 poked to 0, replay_award 0x1c410 still added a credit and read no adj 25 (adj_get log).

### audits.csv (166 rows)
The first six columns are the original ones. Added:
- `menu` / `menu_label`: the number shown in the menu, the position in that sub-list (titles msg 0x154/0x155/0x504):
  - EARNINGS AUDIT #1-13 = audits 1-13 (list 0x3392e)
  - STANDARD AUDIT #1-59 = audits 14-72 (list 0x3394a)
  - FEATURE AUDIT #1-94 = audits 73-166 (0x1005ce4 -> 0x1046598(0, 73, 166))
- `counter` / `counter_nvram` / `counter_flags`: the counter-table entry when the audit is a plain counter.
- `display_type`: 1 "%d", 2 "%d%%", 3 m:ss, 4 money (0x26f74, uses the CURRENT pricing unit value), 5 score, 6 "x% OF GAMES".
- `lifetime_line`: record word +0xc bit 0 adds the LIFETIME line (selector 0x90).
- `formula` / `meaning`: present when the audit is computed (`formula_fn`). The functions are the same as Tron's, at new addresses.
  Division by zero gives 0 (`div_by_zero`).
- `incremented_by`: functions with an audit_add 0xc3c call with that counter as a constant.
- `observed_zero` / `observed_poked` / `observed_lifetime`: formatter output with all counters 0, after poking test values
  (emu/t1.log, `mark POKE`), and the lifetime value. Checks: 2 FREE GAME PERCENTAGE 45% (18 x 100 / 40), 3 AVERAGE BALL TIME
  1:15 (9000/120), 4 AVERAGE GAME TIME 3:20 (10000/50), 11 TOTAL EARNINGS 13 units = "USD 3.25", 13 SOFTWARE METER and
  72 RECENT REPLAY PERCENT always 0, 53 CENTER DRAINS 120-30-25 = 65, feature audit 73 "17\n34% OF GAMES" (17 of 50 plays).

### adjustments.csv (98 rows)
The first eleven columns are the original ones (`tag` now gives the evidence). Added:
- `menu_label`: STANDARD ADJUSTMENT #n follows the order list 0x338ac (64 ids); FEATURE ADJUSTMENT #n = adj 64+n
  (0x1005d18 -> 0x1045c08(0, 65, 98)). Titles msg 0x140 / 0x506.
- `factory_default_usa`: the value after boot with a fresh NVRAM (factory install, country U.S.A.), observed with
  adj_get 0x340 and equal to adj_default 0x3d8 for all 98 (emu/t1.log). Only adj 10 PLAYER LANGUAGE SELECT differs from
  the table default (U.S.A. OS list 0x332dc sets it to YES).
- `wraps`: no if record byte +0x1e has bit 0 set (97, 98: the value stops at min/max), as in the menu code 0x1045c08.
- `formatter` / `labels` / `labels_source`: value labels, from a msg list (drawn by 0x76c) or by running the formatter
  function in the emulator (emu/t5.log). Ranges over 1100 values (GAME ID, LOCATION ID) are sampled (~100 values).
  BEST COMBO CHAMPION (93) stores n-WAY as n<<16 | 1 (2-WAY .. 10-WAY, game formatter 0x10037b0).
- `visible_if`: the rule in adj_visible 0x2be10 (same rules as Tron's 0x34124). The game registers no hook on the
  menu events 0-3, so nothing else hides adjustments.
- `country_overrides`: values set per country by the OS list (+4) and the game list (+8). (+0xc is a list of custom
  attract-message strings, used only by CHUCK-E-CHEESE; +0x10 points to the redemption defaults.) `[observed]` means the value was read back after the factory reset for that country (emu/t4.log).
- `readers`: adj_get 0x340 call sites with a constant id, plus the struct-based sites (credit system, meter table
  0x40cf768, high-score table 0x40cf948, replay levels 16+n, two device-disable predicates). `(observed)`: hit in emu/t2/t6.

### presets.csv
- `kind=install`: INSTALL menu items. Each screen calls 0x1049910(os_list, game_list, msgs...) which applies both lists with
  adj_apply_list 0x598 and checks them with 0x5c8. Unlike Tron, the difficulty presets are not empty: EXTRA EASY .. EXTRA HARD,
  DIRECTOR'S CUT, 3-BALL and 5-BALL set the game adjustments 66-83 (game lists 0x30eb4 ..). HOME PLAY is empty.
  INSTALL FACTORY (0x1049774) runs 0x728.
- `kind=country`: factory overrides per country. Precedence in 0x3d8 -> 0x53dc: country game list > list 0x33790 (empty)
  > country OS list > table default. Rows are `observed` when the value after `country N` + 0x728 matched (all 85 rows).

### service_texts.csv
One row per (msg, drawing site) in the service menus, as in Tron:
- `menu item name` (item table +0xc), `adjustment value label`, `pricing preset name`, `country name`,
  `install screen text` (0x1049910 args), audit/adjustment screen titles, direct text calls
  (`text_draw_msg` 0x215ac, `text_draw_msg_fit` 0x2174c, `text_printf_msg` 0x21660, `msg_get` 0x99f0) found by a search
  3 calls deep from each item's screen/action function in the decompile, and `dynamic: <expr>` when the id is computed.

### menus_runtime.json
The item ids of each menu (1..17) as built at run time by 0xeb3c with the factory settings (observed, emu/t1.log).
The game inserts through event 0x5d (hook 0x1005c60): FEATURE AUDITS (124) after STANDARD AUDITS, FEATURE ADJUSTMENTS
(125) after STANDARD ADJUSTMENTS, GAME-SPECIFIC TESTS (126) after GO TO LAMP MENU, and TICKET DISPENSER TEST (17) before
RETURN TO MAIN MENU when 0xf644(1) (ticket dispenser configured; not at factory). Hidden at factory: 14 DISPLAY SOFTWARE
ERRORS, 111/112 STOP/VIEW TOURNAMENT, 118-120 redemption items.

### emu/
- t1: RAM dump, credits display, runtime menus, adj_get/adj_default for all ids, all audits before and after pokes.
- t2: coins and credits (USA 10, GERMANY 2, EURO 3), free play, credit limit, coin delay off, replay award with adj 25 = 0.
- t3: pricing summaries (0xa438) and names (0x26a4c) for every preset.
- t4: factory reset for each of the 29 countries (NVRAM 0x21100d8 + checksum 0x1c50, then 0x728), all adj values.
- t5: adjustment formatter outputs.
- t6: coins, game start and drains with adj_get logging (counts in t6_adj_get_counts.txt).

## Open items
- **PinMAME DIP country** was not used: countries were emulated by writing NVRAM 0x21100d8 {country, done, ~checksum16}
  and calling 0x728, as in Tron. The boot path 0x550c (DIP -> NVRAM) is `code`.
- **Adjustments with no adj_get reader** (`code`): 1, 5, 6, 8, 9, 24, 25, 27, 37, 43, 45, 47, 71, 97, 98. No code reads
  their NVRAM directly either. Notable: 24 SPECIAL PERCENTAGE, 27 EXTRA BALL PERCENTAGE and 71 ORBIT DIFFICULTY seem to
  have no effect in v1.80 (`inferred`); 25 FREE GAME LIMIT has no effect on replays (observed). 45 TICKET DISPENSER is
  applied by the game's event 5 hook 0x1005c30 when it changes (0xfa04). 9/97/98 volumes are likely applied by the sound
  code through another path (`inferred`).
- **CUSTOM pricing** (adj 28 = 68): the row shows the factory-empty NVRAM record; its summary was not captured.
- **Unresolved dynamic text ids**: rows with `dynamic: ...` and no `msg` are not traced one by one.
- **Switch descriptor flags** (rom_data/io/switches.csv `flags_0x0c`): no code testing these bits as immediates was found.
  The values group the switches: 0x04000000 slingshots and pop bumpers, 0x14000000 targets, ramp entries and energon,
  0x24000000 lanes, rollovers, ramp exits, orbits and outlanes, 0x?fff1f80/0x07ff0000 trough, eject, locks, start buttons
  and the Optimus Prime motor switches, 0 unused. So bit 26 likely marks a playfield scoring switch, bit 28 a target/entry
  and bit 29 a rollover/lane (`inferred`).

## Contradictions with existing docs
- `rom/README.md` gives the adjustment and audit counts as 99 and 167. Those are the registry counts including the unused
  entry 0; there are 98 adjustments and 166 audits (the old adjustments.csv already had 98 rows).
- The old adjustments.csv `default_table` is the factory default for every id except 10 PLAYER LANGUAGE SELECT (USA = YES).
